# PHP 8.5への更新手順

この派生版は、添付された TinyIB-master.zip を基にPHP 8.5へ対応したものです。
本番サイトのソースやデータベースを直接取得していないため、本番データのコピーで更新を確認してから反映してください。

## 投稿を保持するための条件

既存の `settings.php` をそのまま使用します。
特に `TINYIB_TRIPSEED`、`TINYIB_BOARD`、保存方式、接続先、テーブル名、SQLiteのパスを変更しないでください。
`TINYIB_TRIPSEED` を変えると、削除パスワードや管理者認証、トリップの互換性が失われます。
データ移行機能を有効にする必要はありません。

更新用ZIPには `settings.php`、投稿データ、アップロード画像、生成済みHTMLを含めません。
FTPソフトでは既存ディレクトリへファイルを上書きし、「同期先にないファイルを削除」「ディレクトリ全体を置換」などの機能を使わないでください。

| 保持する対象 | 内容 |
| --- | --- |
| `settings.php` | 本番設定と認証情報 |
| `src/`、`thumb/`、`res/` | 投稿画像、サムネイル、スレッドHTMLとJSON |
| `inc/database/flatfile/` 内の `.posts*`、`.accounts*`、`.bans*`、`.keywords*`、`.logs*`、`.reports*` | flatfileの投稿、管理者、規制などのデータ |
| 旧保存先 `inc/flatfile/` | 旧版のflatfileデータがある場合 |
| `.tinyib.db`、`tinyib.db`、設定した別のDBファイル | SQLiteデータ。稼働中はWALなどの付随ファイルも考慮する |
| MySQLなどの既存テーブル | 外部データベースの投稿やアカウント |
| ルートのHTMLとJSON、`.htaccess`、`.user.ini` | 生成済みページとサーバー固有設定 |

## 翻訳ライブラリの構成差

報告された `Gettext\Loader\PoLoader` の警告は、添付ZIPと異なるGettext構成から発生しています。
この版は添付ZIPのGettextを修正し、`inc/gettext.php` と `inc/gettext/` を一式として配布します。
両方をまとめて上書きしてください。
旧版の `Loader/` だけを部分更新しても、この版の翻訳処理にはなりません。
残った旧版の `Loader/` は、この版の `inc/gettext.php` からは使用しません。
独自にGettextを読み込む追加コードがある場合は、事前に互換性を確認してください。

## 本番への反映

1. FTPなどで現在の `tinyib/` を隠しファイル込みで保存します。
   外部データベースを使用している場合は、phpMyAdminなどで対象テーブルもエクスポートします。
   バックアップは公開ディレクトリの外に保管します。
2. 投稿と削除を一時停止し、更新中にデータが変わらないようにします。
   サーバーのアクセス制限などを利用し、管理者だけが動作確認できる状態にします。
3. バックアップのコピーと同じPHP設定を使う検証用ディレクトリで、この版を上書きします。
   検証用サイトは別のデータコピーとDB接続先を使用し、本番DBへ接続させないでください。
   投稿数、過去スレッド、画像、管理者ログイン、投稿と返信を確認します。
4. 検証後、更新用ZIPをPCなどで展開します。
   展開した内容を `maniajiru.jp/tinyib/` の既存ディレクトリに上書き転送します。
   `inc/database/flatfile/` はPHPファイルだけが追加または更新され、既存の隠しデータファイルを残します。
5. お名前.comの契約プランの管理画面で、対象サイトのPHPを8.5に設定します。
   PHP 8.5の提供状況、設定範囲、拡張モジュールは契約環境で確認してください。
   この作業では契約サーバーの設定を直接確認していません。
6. `imgboard.php?manage` で既存の管理者としてログインし、「Rebuild All」で過去スレッドと一覧を再生成します。
   管理用キーを設定している場合は、従来の管理画面URLを使います。
   再構築は既存投稿から表示用ファイルを作り直します。
7. 過去投稿の件数、本文、画像を確認し、テスト投稿と返信、削除パスワード、CAPTCHAを確認します。
   PHPのエラーログも確認してから投稿受付を再開します。

障害時は投稿受付を止めたまま、保存したソースと設定へ戻します。
DBの復元が必要な場合は更新前のバックアップを使用し、受付再開後に増えた投稿を消さないようにしてください。
この版の更新処理は投稿の一括削除やDBモードの変更を実施しません。
通常の投稿時には、従来どおり `TINYIB_MAXTHREADS` による古いスレッドの削除があり得るため、保持方針に合わせて既存設定を確認してください。

## PHPの実行条件と修正内容

PHP 8.5、GD（JPEG、PNG、FreeType対応）、mbstringを確認してください。
保存方式に応じてmysqli、pdo_mysqlまたはsqlite3が必要です。
外部CAPTCHAや埋め込み機能にはcURLが必要な場合があります。
旧 `mysql` と `sqlite` モードはPHP 8.5で廃止済みの拡張を使用します。
該当する場合は、稼働中の旧PHP環境でバックアップと移行検証を行い、対応する保存方式へ移してからPHPを切り替える必要があります。
設定名だけを変更すると既存データを参照できなくなる場合があるため、独断で変更しないでください。

この版では次の原因を修正しています。

- メール欄などを省略した投稿の未定義キーとnull渡し。
- 翻訳検索のnull配列キーと非推奨の型キャスト。
- reCAPTCHAの暗黙的nullable引数。
- GDとcURLの非推奨になった解放関数。
- CAPTCHAの動的プロパティと小数座標の暗黙的な整数変換。
- PDOのMySQL固有定数。
- `strftime()` による日付表示。

日付設定は従来の `%g/%m/%d(%a)%H:%M:%S` を維持できます。
主なstrftime形式の指定子を対応表で変換し、未対応の指定子はそのまま残します。
`%c`、`%x`、`%X` は固定の英語形式になり、OS依存の複合形式や修飾子の完全互換は保証しません。
intlが有効なら曜日名などを `TINYIB_LOCALE` に合わせ、無効なら英語で表示します。
PHPの警告表示はサーバーの `display_errors` 設定に従います。
本番では `display_errors=Off`、`log_errors=On` を設定し、警告の確認はログで行ってください。

## スマートフォン表示の更新

レスポンシブ表示の変更は `css/global.css`、`inc/html.php`、`js/tinyib.js` に含まれます。
3ファイルを上書きし、管理画面の「Rebuild All」で既存の一覧、スレッド、カタログを再生成してください。
再生成後のHTMLにはCSSとJavaScriptの更新識別子が付き、キャッシュされていた古いファイルから切り替わります。
設定と投稿データは引き続き保持します。

画面幅640px以下では、投稿フォームを縦並びにし、入力欄を画面幅に合わせます。
投稿本文と長いURLは折り返し、画像は展開後も画面幅に収めます。
管理画面の幅広い表は内容領域内で横にスクロールできます。
PC用の配色と横並びレイアウトは維持します。

## 開発時の検証と配布ZIPの作成

PHP 8.5のCLIと必要な拡張がある環境で、次を実行します。

```sh
php tests/php85.php
python3 tools/build-update.py
```

Dockerを使う場合は `tools/Dockerfile.php85` で検証用イメージを作成できます。
クラウド環境のプロキシを使うビルドでは、信頼済みCAバンドルをBuildKit secretの `proxy_ca` として渡します。
通常環境でもシステムのCAバンドルを同じ名前で渡してください。

```sh
docker build --secret id=proxy_ca,src=/etc/ssl/certs/ca-certificates.crt -f tools/Dockerfile.php85 -t tinyib-php85 .
docker run --rm -v "$PWD:/app" -w /app tinyib-php85 php tests/php85.php
```

テストは一時ディレクトリ内にテスト専用設定と投稿を作り、終了時に削除します。
既存の `settings.php` は読み込みません。
日本語翻訳、任意欄省略、新規投稿、一般利用者と管理者の返信拒否、返信UIの除去、画像、CAPTCHA、管理者ログイン、上書き後のデータ保持と再構築を確認し、警告や非推奨通知を例外として検出します。
MySQL系のテストは `TINYIB_TEST_MYSQL_HOST` に使い捨てDBのホストを指定した場合に追加されます。
この追加テストはパスワードなしのrootでランダム名のDBを作成して削除するため、公開ポートのない隔離されたテストコンテナだけで使ってください。
本番DBを指定してはいけません。

配布物は `dist/tinyib-php85-update.zip` とSHA256ファイルに出力します。
更新用ZIPには `.htaccess` を含めないため、既存のアクセス制限を保てます。
flatfileやSQLiteへの直接アクセスを拒否できていることは、本番サーバー側で確認してください。

## 返信機能の無効化

新規投稿のみ受け付けます。返信フォーム、引用操作、管理者の返信先指定欄、自動返信取得を取り除き、直接送信された返信も拒否します。
既存の返信データは削除しません。更新後は「Rebuild All」を実行し、生成済みページの返信フォームとリンク表示を更新してください。
